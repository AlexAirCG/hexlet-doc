# Как протестировать функцию с запросами к внешнему API

*Вопрос и ответ для собеседования по теме Advanced Testing JS (испытания 5 и 6)*

## Вопрос

**«Как протестировать функцию, которая делает запросы к внешнему API (например, к GitHub)?»**

## Короткий ответ (30 секунд)

«В тестах нельзя ходить в настоящую сеть: тест будет медленным, зависящим от интернета и от того, что ответит сервер. Есть два основных способа это обойти.

Первый: **подменить зависимость**. Если клиент (например, Octokit) можно передать в функцию параметром, я передаю вместо него фейк, который сразу возвращает заготовленные данные.

Второй: **перехватить запрос** библиотекой вроде `nock`. Это нужно, когда клиент создаётся внутри функции и передать его нельзя. `nock` ловит HTTP-запрос на нужный адрес и отвечает заготовленными данными, а реальные запросы я запрещаю через `nock.disableNetConnect()`».

## Если спросят «в чём разница»

**Подмена зависимости (фейк `OktokitFake` из испытания 5):**

- Плюс: тест не зависит от адресов и библиотеки. Если заменить Octokit на другую библиотеку, тест останется рабочим.
- Минус: функция должна принимать клиента параметром. Если клиент создаётся внутри, так не сделать.

**Перехват запроса (`nock` из испытания 6):**

- Плюс: работает с любым кодом, функцию менять не нужно.
- Минус: тест знает адрес (`/users/linus/repos`). Если библиотека поменяет адрес, тест сломается, хотя функция работает правильно.

## Что ещё стоит упомянуть

- Какой способ выбрать: «Если могу, передаю фейк. Если нет, использую `nock`».
- Хороший тест должен проходить на правильной реализации и падать на неправильной. Поэтому я проверял и список с языками, и пустой список.
- Ответ сервера в тесте зафиксирован заранее, поэтому результат не зависит от внешнего мира.
